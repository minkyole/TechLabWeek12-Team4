# 크래시 덤프와 심볼 창고

처리되지 않은 예외로 프로세스가 종료되면 미니덤프(`.dmp`)를 남기고, 빌드별 PDB를 심볼 창고에 보관해 이후에도 덤프의 콜스택을 소스 줄까지 확인한다.

## 동작

`WinMain` 첫 줄의 `FWindowCrashHandler::Install()`이 `Saved/Crashes` 폴더를 준비하고 SEH 최종 처리기를 등록한다. 에디터, 엔진, ImGui 등 프로세스 안 어디서 난 크래시든 같은 처리기가 받는다.

크래시가 나면 다음 순서로 처리한다.

1. `Saved/Crashes/Crash_YYYYMMDD_HHMMSS.dmp`를 기록한다.
2. 예외 코드, 주소, 덤프 경로를 메시지 박스로 표시한다.
3. 확인을 누르면 프로세스를 종료한다.

`Saved/`는 `.gitignore` 대상이므로 덤프는 커밋되지 않는다.

**디버거(F5)로 실행 중이면 처리기가 호출되지 않는다.** VS가 예외를 먼저 받기 때문이다. 덤프를 확인할 때는 **Ctrl+F5(디버깅하지 않고 시작)**로 실행한다.

## CauseCrash

콘솔에서 의도적으로 크래시를 내어 처리기를 검증한다. 대소문자를 구분하지 않는다.

| 명령 | 동작 | 예외 코드 |
|---|---|---|
| `CauseCrash`, `CauseCrash null` | 널 포인터 쓰기 | `0xC0000005` |
| `CauseCrash div` | 정수 0 나누기 | `0xC0000094` |
| `CauseCrash stack` | 무한 재귀 | `0xC00000FD` |

알 수 없는 인자는 크래시 없이 사용법을 출력한다.

현재 스택 오버플로, `abort()`/`assert` 실패, CRT 잘못된 인자, 순수 가상 함수 호출은 덤프가 남지 않을 수 있다.

## 덤프 열기

1. VS에서 **파일 > 열기 > 파일**로 `.dmp`를 연다.
2. 요약 화면의 **네이티브 전용으로 디버그**를 누른다.
3. 소스 창이 크래시 줄에서 멈추고 호출 스택에 함수 이름이 보이면 정상이다.

같은 PC에서 다시 빌드하기 전이면 심볼 창고 없이도 `Build/Bin`의 PDB로 열린다. 다시 빌드하면 PDB가 덮어써져 이전 덤프는 주소만 보인다. 이 경우를 위해 심볼 창고를 쓴다.

## 심볼 창고

exe와 PDB는 빌드마다 바뀌는 GUID로 짝을 맞춘다. 같은 커밋을 다시 빌드해도 GUID가 달라지므로, 덤프를 만든 바로 그 빌드의 PDB가 있어야 한다. `PublishSymbols.bat`는 빌드 결과물을 GUID별 폴더에 보관한다.

### 준비

1. Windows SDK에 **Debugging Tools for Windows**를 추가 설치한다.
   설정 > 앱 > 설치된 앱 > Windows Software Development Kit > 수정 > Change에서 선택한다.
   설치 후 `C:\Program Files (x86)\Windows Kits\10\Debuggers\x64\symstore.exe`가 생긴다.
2. VS **도구 > 옵션 > 디버깅 > 기호**에서 설정한다.
   - 기호 파일 위치에 창고 경로를 추가하고 **체크**한다. 기본 창고는 `<프로젝트 루트>\Saved\Symbols`이다.
   - **Microsoft 기호 서버**를 체크한다. 시스템 DLL 프레임을 읽는 데 필요하다.
   - **모든 모듈 로드(제외되지 않는 경우)**를 선택한다. "지정된 모듈만 로드"면 `HitoriEditor.pdb`를 건너뛴다.

`symstore.exe`는 창고에 넣는 사람만 필요하다. 덤프를 읽기만 하는 사람은 2번 설정만 하면 된다.

### 등록

```bat
PublishSymbols.bat [Debug|Release|Executable|...]
```

인자가 없으면 `Release`이다. `Build/Bin/<구성>-windows-x86_64`의 `HitoriEditor.exe`와 `HitoriEditor.pdb`를 창고에 등록한다. 버전에는 커밋 해시를 기록하며, 커밋하지 않은 변경이 있으면 `-dirty`를 붙인다.

내 PC를 떠나는 빌드(배포, 시연, 팀원 전달)를 만들었을 때만 실행한다. 개발 중 빌드마다 실행할 필요는 없다. Debug PDB는 한 번에 약 150MB를 차지한다.

창고 경로는 `HITORI_SYMBOL_STORE` 환경 변수로 바꾼다. 팀이 함께 쓰려면 공유 폴더를 지정하고, VS 기호 경로에도 같은 경로를 넣는다.

### 확인

1. 빌드한 뒤 `PublishSymbols.bat <구성>`을 실행한다.
2. Ctrl+F5로 실행하고 `CauseCrash`로 덤프를 만든다.
3. 코드를 수정해 다시 빌드한다. 이제 로컬 PDB는 덤프와 맞지 않는다.
4. 덤프를 열어 소스 줄이 보이는지 확인한다.
5. **디버그 > 창 > 모듈**에서 `HitoriEditor.exe`의 기호 파일 경로가 창고 아래인지 확인한다.

## 팀원 간 덤프 공유

창고에 등록하지 않은 개발 빌드의 덤프는 크래시가 난 사람이 직접 분석한다. 다른 사람이 분석해야 하면 같은 빌드의 `.dmp`, `HitoriEditor.exe`, `HitoriEditor.pdb`를 함께 전달하고, 받은 쪽은 세 파일을 한 폴더에 둔 뒤 덤프를 연다.

## 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 크래시 후 덤프가 없다 | F5로 실행했다 | Ctrl+F5로 실행한다 |
| "HitoriEditor.exe를 찾을 수 없음" | 기호 경로에 창고가 없거나 체크되지 않았다 | 기호 설정에서 창고 경로를 추가하고 체크한다 |
| "HitoriEditor.pdb 포함 안 됨" | "지정된 모듈만 로드" 상태다 | "모든 모듈 로드"로 바꾼다 |
| 호출 스택이 주소만 나온다 | 덤프를 만든 빌드가 창고에 없다 | 해당 빌드의 PDB가 없으면 복원할 수 없다. 이후 배포 빌드는 반드시 등록한다 |
| `PublishSymbols.bat` 첫 줄 오류 | 파일이 BOM 있는 UTF-8로 저장됐다 | BOM 없는 UTF-8, CRLF로 다시 저장한다 |
